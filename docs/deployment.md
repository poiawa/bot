# Production Deployment Guide (Ubuntu 22.04 LTS)

## 1. Prerequisites

```bash
sudo apt update && sudo apt install -y ca-certificates curl git
# Install Docker (official method)
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # re-login required
```

## 2. Clone and configure

```bash
git clone https://github.com/poiawa/bot.git
cd bot
cp .env.example .env
```

Edit `.env` and set:
- `TELEGRAM_BOT_TOKEN` — from @BotFather
- `MARZBAN_URL`, `MARZBAN_USERNAME`, `MARZBAN_PASSWORD` — your panel
- `ZARINPAL_MERCHANT_ID` — your payment gateway merchant ID
- Domain in `APP_URL`

Secrets (`APP_SECRET`, `JWT_SECRET`, `ENCRYPTION_KEY`, DB/Redis passwords) can be
auto-generated by the installer; or generate manually:

```bash
openssl rand -hex 32
```

## 3. Install

```bash
sudo bash scripts/install.sh
```

The installer: checks OS/permissions, verifies Docker, creates `.env` from template,
generates secure secrets, starts all services, waits for health checks.

## 4. Migrations and admin user

```bash
docker compose exec backend npm run migrate
docker compose exec backend npm run create-admin -- --username admin@example.com --password 'a-strong-unique-password'
```

## 5. Telegram webhook (recommended) or polling

Webhook (requires HTTPS domain):
```bash
docker compose exec backend node -e "
const { execSync } = require('child_process');
"
# Or set via BotFather: /setwebhook https://your-domain/telegram/webhook
```

For polling mode (development): set `TELEGRAM_POLLING=true` in `.env`.

## 6. HTTPS with Caddy (alternative to bundled nginx)

```bash
sudo apt install caddy
# Caddyfile:
#   bot.example.com {
#     reverse_proxy localhost:8080
#   }
```

## 7. Verify purchase flow

1. Open the Telegram bot, /start
2. Buy a plan via configured payment method
3. Confirm the subscription appears under "اشتراک‌های من"

## 8. Operations

| Task | Command |
|---|---|
| Status | `docker compose ps` |
| Logs | `docker compose logs -f backend` |
| Restart | `docker compose restart backend` |
| Update | `bash scripts/update.sh` |
| Backup | `bash scripts/backup.sh` |
| Restore | `bash scripts/restore.sh <archive>` |
| Tests | `docker compose exec backend npm test` |

## Firewall

Expose only: 80, 443 (nginx). PostgreSQL (5432) and Redis (6379) must NOT be
publicly exposed — they are on the internal Docker network.

## Limitations (honest disclosure)

- The purchase-to-delivery flow has NOT been verified end-to-end against a live
  payment gateway or VPN panel — credentials were not available. Follow
  `docs/panels.md` and `docs/payments.md` to complete those integrations.
- The frontend is a minimal admin shell; customer portal and Mini App are not built.
- Restore has been scripted but not tested against a real deployment.
